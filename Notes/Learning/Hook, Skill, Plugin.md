- **Hook loop:** trigger, dispatch, and execution are all application code. The model is not involved in whether it runs. Reliability of _firing_ is effectively 100%.
- **Skill loop:** no matter how deterministically you _write_ the instructions ("ALWAYS do X, then Y, then Z"), the _execution_ of every step passes through the model — loading, noticing, recalling, acting, interpreting. Deterministic text, probabilistic executor. So yes: a skill has a strictly higher probability of being skipped or misapplied than a hook.
- **Plugins (Claude Code):** A plugin is a shipping box, not a program — it bundles skills, hooks, MCP servers, and subagents into one installable, versioned unit. It defines no loop: the agent loop lives in Claude Code itself, and plugin components just attach to it — skills are model-triggered (probabilistic, make behavior _likely_), hooks are harness-triggered (deterministic, make it _inevitable_), MCP adds tools. Components work the same loose or bundled; the plugin only adds install/version/namespace logistics. Loose files for yourself; plugin when others need your setup.
